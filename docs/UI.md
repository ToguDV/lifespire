# UI notes — shell, tokens and components

The shipped app is the accepted visual reference. `design/DESIGN.md` is its
specification; the React UI implements it rather than inventing a parallel
system.

The static HTML proposal that used to live in `design/` has been retired; the
app and `design/DESIGN.md` are the only references now. No UI kit or router is
used; interface icons come from `lucide-react` through the semantic adapter.

## Shell and navigation

`apps/web/src/ui/App.tsx` renders the desktop sidebar, mobile topbar and tabbar, skip
link, `<main id="main-content">`, theme controls and the current screen. The
view is a discriminated union in `apps/web/src/domain/types.ts`; `view` and `history`
are transient store state and are never persisted.

Navigation targets: Map, Camp (home), Goals, Reliquary and Settings. Node detail,
day summary and run summary are reached from Map or Camp. Without a profile the
shell is hidden by `body[data-screen="welcome"]` and onboarding is shown. A
blocked save forces recovery. Map, node and day-summary views fall back to camp
(or the run summary when the run is closed). Profile-without-run lands on camp,
which shows the honest "No run yet" state and a real start button; map remains
unreachable until a run exists.

## Reliquary and local data

The Reliquary ports the accepted `screen--reliquary`, `profile-strip`,
`collection-head` and `loot-card` hierarchy. On top of the static prototype it
adds four native filter buttons (All/Common/Rare/Epic) with found/total counters,
the full twelve-slot catalogue and a duplicate-conversion panel. An unfound relic
only shows a locked niche and "Undiscovered"; its name, rarity, description and
art stay hidden. Owned cards reuse `LootCard` with a `detailed` variant for the
description and found date. The filter state is local to the screen and is never
persisted.

Settings extends the same panels and tokens with the Nearby devices panel (the
device card, the QR/code pairing dialog, paired/nearby lists, auto-sync switches
and the conflict entry point) and the data controls. Export
downloads the versioned JSON document; import uses a visually hidden file input
inside a `btn` label, so the 44 px target, focus ring and keyboard activation are
preserved. The preview is a `Dialog` with a definition list, and the destructive
reset also requires typing `RESET` before its final button enables.

## Android shell

The Android app reuses the same `view` union and store navigation, not a router.
`AppShell.tsx` renders a compact topbar (brand, day label, gold/level, settings)
and a four-item tabbar (Map, Camp, Goals, Relics); Settings is a full screen
from the topbar. The node detail, wheel recap, day summary and run summary are
reached from Map/Camp with the same guards. The hardware back button maps to
`back()` and is blocked on the wheel recap. Safe areas are handled once at the
root; `Screen` only adds padding and the scroll container.

The component vocabulary mirrors web: `Button`, `IconButton`, `Icon`, `Panel`,
`PanelHead`, `ScreenHead`, `Progress`, `Pips`, `DayPips`, `Stat`, `StatStrip`,
`EffortDots`, `AimRow`, `LootCard`, `Dialog`, `Toast`, `RewardToast`,
`IconPicker`, `AnimatedNumber` and `MapCanvas`. `MapCanvas` reuses the pure
map layout; the wheel reuses the sector and rotation math. Long dialogs scroll
inside the modal so forms remain usable on 360 dp screens.

## PWA

The production build registers a Workbox service worker generated by
`vite-plugin-pwa`; the development server does not. The manifest theme and
background use the night canvas token (`#131511`), matching the dark icon tile,
while the in-app `theme-color` meta still follows the light/dark canvas
(`#f1f0ea` / `#131511`). The brand mark is the original spire; every other
interface icon is a Lucide component selected by the semantic name.
See [`PWA.md`](./PWA.md) for offline verification and the HTTPS requirement for
phone installation.


Theme is stored as `light | dark | system`. Explicit themes set
`html[data-theme]`; `system` removes the attribute so the `prefers-color-scheme`
rules in `tokens.css` apply. Screen changes move focus to `<main>`.

## Components

`apps/web/src/ui/components/`:

- `Button` — primary / secondary / quiet / danger, optional small and full.
  `quiet` maps to the prototype's `btn--ghost`.
- `IconButton`, `Icon` — semantic adapter over Lucide; `spire` stays custom.
- `Panel`, `PanelHead`, `ScreenHead`.
- `Progress`, `Pips`, `DayPips`, `Stat`, `StatStrip`, `Resource`,
  `LevelResource`, `EffortDots`, `AimRow`, `LootCard`.
- `Dialog` — focus trap, `Esc`, backdrop click, focus restoration and
  `role="dialog"`.
- `Toast` — polite feedback for store messages.

Every component emits the ported classes (`btn`, `panel`, `chip`, `pips`,
`screen-head`, etc.), so custom CSS is only needed for new UI states.

`AimRow` keeps the old "aim" name on purpose: the interface says **goal**,
**trial** and **weekly target**, while identifiers, CSS classes and DOM
hooks keep the "aim" family. See [`../GLOSARY.md`](../GLOSARY.md).

## Accessibility

Visible `:focus-visible`, a skip link, 44 px primary targets, labelled icon
buttons, semantic headings, keyboard-operable navigation and focus trapping in
dialogs. `prefers-reduced-motion` is handled by `tokens.css`; new animations use
the same duration/easing tokens.

Android uses 48 dp targets, TalkBack roles/labels/state, safe areas, a scrollable
dialog body, `AccessibilityInfo.isReduceMotionEnabled` for the wheel/counters
and the same contrast tokens. Notification permission is only requested from
Settings, never on a cold start.
