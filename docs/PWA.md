# PWA — installable and offline after the first load

LifeSpire ships a production-only service worker generated by
[`vite-plugin-pwa`](https://vite-pwa-org.netlify.app/) with `registerType:
'autoUpdate'`. The manifest and icons are part of the production build; the
development server never registers a service worker.

## What is cached

The generated Workbox service worker precaches the app shell and static files:

- `index.html`, the built JS and CSS bundles, and the generated
  `manifest.webmanifest`;
- the self-hosted Alegreya and Alegreya Sans WOFF2 files;
- the favicon and the 192/512 PNG icons, including maskable variants.

There is no runtime cache and no caching of application state. The save remains
in `localStorage` under `lifespire:mvp0`, so a service-worker update only swaps
static assets. The versioned schema, import validation and recovery screen still
guard the persisted document exactly as before.

## Verify locally

```bash
pnpm build
pnpm preview --port 4173
```

1. Open `http://localhost:4173` and wait for the first load to finish.
2. Reload once so the service worker controls the page.
3. In Chromium DevTools → Network, enable **Offline** and reload. The app shell,
   fonts and icons must load from the service worker.
4. Check Application → Manifest for the name, colours, `standalone` display and
   the 192/512/maskable icons; Application → Service Workers should show the
   worker as activated.
5. Export a save, reset local data, import the file and confirm that the profile,
   run and collection return unchanged.

`localhost` is treated as a secure context by Chromium, so installation can be
tested there without HTTPS. The browser's install prompt is environment-driven;
the app intentionally has no custom install button.

## Installing on a phone

A phone cannot install the app from a plain `http://<LAN-IP>:4173` origin.
Installation and service workers require **HTTPS** (or `localhost` on the same
device). The web build is static now: serve `apps/web/dist` from any HTTPS
static host (or `pnpm preview` for a local check). There is no API origin,
cookie contract or reverse-proxy rule to configure. For a local demo, use a
trusted HTTPS tunnel or a local certificate; do not treat that as a production
deployment.

## Icons

The icon set is original and derived from the tower symbol in
`apps/web/public/favicon.svg`. Regenerate the PNGs with:

```bash
python3 apps/web/scripts/generate-pwa-icons.py
```

The script draws the favicon geometry with Pillow and writes the standard,
maskable and Apple touch icons into `apps/web/public/icons/`.
